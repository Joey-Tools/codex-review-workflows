# Codex Review Workflows Guidelines

- Use `$agile-delivery-workflow` when the user explicitly asks for an MVP, early usable product, quick iteration, agile delivery, scout work, or a similar first-slice delivery.
- Use `$review-orchestration-playbook` as the only review entrypoint for local Codex review, double/triple review, and PR readiness.
- Run every Claude review in the same combined boundary: Claude Code uses the current user's real `HOME` for its control-plane authentication and configuration, while model tools run read-only inside a helper-owned detached Git worktree. Clean and WIP are content variants of that boundary, not separate runtime modes.
- Default to a clean source checkout and the exact detached head. Use `--include-source-wip` only with explicit consent to capture staged changes, unstaged changes, and non-ignored untracked files into a digest-bound review-only snapshot. WIP evidence never satisfies formal PR-readiness or merge-ready exact-commit gates.
- Claude authentication precedence is `ANTHROPIC_API_KEY` > `CLAUDE_CODE_OAUTH_TOKEN` > ordinary local login. The helper selects and opaque-forwards only the winning explicit value; it never parses, logs, writes to disk, stages, brokers, or persists that value. Authentication failure is `blocked-authentication`, never a Copilot fallback reason.
- An explicit `double review`, `双重 review`, `triple review`, or `三重 review` request is contemporaneous user consent for scoped code-review egress to OpenAI, Anthropic, and Microsoft/GitHub. It covers the named repository's clean frozen head, generated diff, necessary nearby context, and review prompt/result. WIP files, including non-ignored untracked files, require the separate `--include-source-wip` opt-in and sensitive-content preflight. Consent excludes credentials, unrelated repositories, broad workspace dumps, and home-directory content. Real `HOME` is available to the ordinary Claude CLI but remains outside review scope: the helper does not package it, the prompt forbids reading it, and sensitive paths have explicit file-tool and sandbox denies.
