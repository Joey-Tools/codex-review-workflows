# Codex Review Workflows Guidelines

- Use `$agile-delivery-workflow` when the user explicitly asks for an MVP, early usable product, quick iteration, agile delivery, scout work, or a similar first-slice delivery.
- Use `$review-orchestration-playbook` as the only review entrypoint for local Codex review, double/triple review, and PR readiness.
- An explicit `double review`, `双重 review`, `triple review`, or `三重 review` request is contemporaneous user consent for scoped code-review egress to OpenAI, Anthropic, and Microsoft/GitHub. It covers any necessary tracked code from the named repository's frozen review head, its generated diff, and the review prompt/result sent to OpenAI Codex, Anthropic Claude Code, and, only when the secure Claude runtime is deterministically absent/unavailable or both pinned Claude Opus models are entitlement-blocked, Microsoft/GitHub Copilot; triple review additionally authorizes current-head GitHub Codex review. It excludes credentials, untracked files, unrelated repositories, and broad workspace or home-directory content. For an approval-gated Claude-family helper invocation, repeat this consent together with the exact repository and `base_sha..head_sha` in the escalation justification; do not rely on a generic external-review justification.
- Missing, malformed, unsafe, refresh-token-less, or actually rejected Claude authentication is `blocked-authentication`, never a Copilot fallback reason. An expired access token alone is not login expiry: let the restricted final runtime refresh it and persist any rotation through validated guarded writeback. Local-login writeback requires an exact signed artifact in the credential-lock protocol catalog; an uncatalogued artifact, lock contention, stale lock, carrier race, or credential I/O uncertainty is inspection-inconclusive and must pause without a login prompt or Copilot fallback. Never delete a stale shared lock automatically. For a catalogued artifact, maintain the certified heartbeat on the primary `.oauth_refresh.lock` and legacy sibling lock, recheck the complete macOS Keychain-plus-file logical snapshot or Linux/WSL2 host file, and serialize supported Claude Code login/refresh writers with the commit window. Persist macOS broker rotations before acknowledging them and keep the Linux/WSL2 staged-carrier watcher plus final drain active until cleanup is safe. Do not claim atomic compare-and-swap against unrelated writers that bypass both locks. On local-login `Login expired`, HTTP 401, or refresh failure, tell Joey to run `claude auth login` on that host and pause for an explicit retry; for an explicit API key, tell him to unset or replace `ANTHROPIC_API_KEY` instead.
