# Codex Review Workflows Guidelines

- Use `$agile-delivery-workflow` when the user explicitly asks for an MVP, early usable product, quick iteration, agile delivery, scout work, or a similar first-slice delivery.
- Use `$review-orchestration-playbook` as the only review entrypoint for named single, double, and triple review plus PR readiness.
- A named single review is exactly one clear/fresh-context Codex `reviewer` agent. Launch it with `fork_turns="none"` or the platform-equivalent zero inherited turns, run it read-only in its own clean Git worktree, and let it load every applicable skill, scoped `AGENTS.md`, and project-guidance file. Before launch, prove the frozen range and both endpoint trees are locally complete with lazy fetching disabled; do not let reviewer Git commands fetch missing objects or prompt for credentials. The orchestrator must identify the authoritative active playbook path/version; when this repository is reviewing its own policy migration, use the repo-local playbook from the frozen review head rather than an older installed copy. Give the reviewer only review-control metadata: the repository/worktree, frozen `base_sha..head_sha`, authoritative instruction source/version, instruction-loading order, read-only/evidence limits, focus/non-goals, and output contract. The reviewer must obtain and inspect the diff itself with bounded Git/tool calls; never prebuild or inject the full diff into its prompt.
- A named double review is that single-review agent plus an actual Anthropic Claude Code process launched directly in a different independent read-only workspace over the same frozen `base_sha..head_sha`; the supplied-diff `isolated_review` helper is not this lane. A separately requested GitHub Copilot diagnostic never satisfies or increments the named double-review shape.
- For the Claude lane's accepted real-`HOME` native sandbox, treat outside-workspace read exclusion as prompt/model scope. Native `allowRead` is not a global host-read whitelist: launch must request global `denyWrite` and critical-sensitive-root `denyRead`; those requested controls define the native-sandbox enforcement boundary, while sandboxed Bash may technically read another host path not covered by `denyRead`. Record them as requested configuration because Claude Code 2.1.212 init/capability output does not attest the final merged sandbox or managed permission arrays.
- Capture canonical Claude raw stdout outside the model-visible worktree and require `skills/review-orchestration-playbook/scripts/validate_claude_stream.py` to return `classification: accepted` for the exact cwd, model, and authentication source before any findings count. Prose inspection, partial output, or an ad hoc parser never satisfies the lane; validator acceptance still does not prove the merged sandbox.
- A named triple review is the named double review plus a trustworthy terminal current-head GitHub Codex result requested with exact `@codex review`. The third lane supports only exact host `github.com`; every other host, including `sqbu-github.cisco.com` and every GitHub Enterprise host, and every operating identity in `{hoteng, hoteng_cisco}` is unsupported. Accept provider-authored review/comment evidence only from exact REST `user.login == "chatgpt-codex-connector[bot]"` with exact `user.type == "Bot"`, and app/check evidence only from exact `app.slug == "chatgpt-codex-connector"`; unknown identities are inconclusive.
- Resolve a bare named-review scope in this order: explicit frozen range, explicitly named PR, then exactly one authenticated open-PR candidate for the exact current head repository/branch. Multiple candidates are `blocked-input` (the required explicit PR/range/target selector is absent) and no lane starts. A proven no-PR result does not supply a range; require an explicit committed range or explicitly named target/base and never guess it. A bare named-review request is report-only and does not authorize branch creation, an anchor commit, push, PR creation, or PR branch/metadata changes. Reserve `blocked-authorization` for intended dirty/untracked state that would require an unauthorized anchor commit.
- Bare triple authorizes only the scoped review-request comment on an already-existing supported PR. Every existing PR still requires intended-head/current-head alignment before local lanes or readiness-state consumption, even when an unsupported host or identity has already reduced triple to effective double; only actual PR absence skips that comparison. If a still-eligible PR's current `headRefOid` does not equal the frozen `head_sha` and mutation is not separately authorized, leave it unchanged and report requested triple/effective triple-inconclusive with GitHub lane status `blocked-authorization`. For the same mismatch on an already unsupported PR, keep `requested: triple`, `effective: double`, and report readiness `blocked-authorization`; do not treat the mismatch as making the already-unavailable lane triple-inconclusive or as permitting readiness to continue. If GitHub Codex is unavailable because there is no PR or the integration/host/identity is unsupported, report `effective double`; never claim triple. An authenticated rejection from the exact accepted provider identity may prove that no run started and the integration/service is unavailable; missing response or generic failure is inconclusive. After exact-identity acknowledgement/run/review activity proves start, malformed/stale/ambiguous/incomplete evidence is `triple-inconclusive`, not double fallback.
- The legacy `isolated_review` Codex helper, if retained for low-level compatibility or diagnostics, does not count toward single, double, or triple review. PR readiness adds CI, conversation, and branch/base gates, but no retired extra Codex gates.
- The low-level `isolated_review` helper retains its helper-private credential staging, lock, guarded-writeback, and recovery contracts in `helper-contract.md` and `claude-runtime-trust.md`. Those guarantees do not apply to the named direct Claude lane: its real `HOME` is the trusted ordinary Claude CLI authentication/runtime control plane, including credential refresh and possible cache or tool-result artifacts, and the lane must not claim helper broker/carrier guarantees or that `--no-session-persistence` makes real `HOME` immutable.
- Any unambiguous request classified as single, double, or triple review—including `single review`, `single code review`, `单重 review`, `单一 review`, `double`, `double review`, `double code review`, `双重 review`, `triple`, `triple review`, or `三重 review`—is contemporaneous user consent for scoped code-review egress to exactly that named shape. Single authorizes OpenAI Codex; double additionally authorizes Anthropic Claude Code; triple additionally authorizes GitHub Codex on an exact-host `github.com` PR. It covers necessary tracked code from the named repository's frozen review head, bounded tool-derived review evidence, and the review prompt/result. The Codex `reviewer` agent receives the clean worktree and refs rather than an injected full diff; actual Claude Code reviews the same range from its independent read-only workspace. It does not authorize GitHub Copilot or another substitute reviewer. It excludes credentials, untracked files, unrelated repositories, and broad workspace or home-directory content. For an approval-gated Claude invocation, repeat this consent together with the exact repository and `base_sha..head_sha` in the escalation justification; do not rely on a generic external-review justification.
