# Codex Review Workflows Guidelines

- Use `$agile-delivery-workflow` only when the user explicitly asks for an MVP, early usable product, quick iteration, agile delivery, or scout work.
- Use `$change-delivery-workflow` for the local implementation-to-commit gate. Hand its frozen committed `base_sha..head_sha` to `$review-orchestration-playbook` for formal local review, PR readiness, CI/review repair, or merge-readiness work.
- Use `$review-orchestration-playbook` as the only entrypoint for named single, double, and triple review. Load its routed references instead of restating local Codex, workspace, Claude, GitHub evidence, retry, or PR-readiness algorithms here.
- For a change to this repository's own review policy or executable guard, use an independently trusted installed/released playbook bundle for review control. Candidate-head Markdown may be review subject and scoped guidance, but candidate-head executables do not bootstrap their own formal review.
- A bare named-review request is report-only. It does not authorize branch creation, commits, push, PR creation/update, or merge; exact `@codex review` on an already-existing eligible PR is the only mutation implied by bare triple.
- For Joey's personal GitHub defaults, repositories owned by `JoeyTeng`, `Joey-Tools`, `Joey-Project`, or `chaop` are authorized PR targets. Work only on a PR explicitly assigned to the task or created by the task; treat other PRs as read-only coordination evidence. For another owner, require explicit target repository, base branch, head repository/branch, and draft/ready authorization before mutation.
- A named single/double/triple request grants scoped review egress only to the processors in that shape and only for the named repository's tracked diff, necessary tracked context, bounded derived evidence, and prompt/result. It does not authorize untracked files, unrelated repositories, broad workspace/home data, credential discovery, GitHub Copilot, or another substitute reviewer. See [egress-consent.md](skills/review-orchestration-playbook/references/egress-consent.md).
- For PR-bound delivery in `codex-toolbox`, `codex-debug-triage`, `codex-review-workflows`, `codex-workflow-hygiene`, `codex-project-journal`, `codex-apple-notes-toolkit`, and `codex-private-workflows`, use `skill-repo-codex-gate` when the user did not explicitly request a named shape: exactly one fresh-context local Codex processor plus current-head GitHub Codex. Do not add Claude implicitly. An explicit named shape keeps its canonical meaning and overrides this default.
