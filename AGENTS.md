# Codex Review Workflows Guidelines

- Use `$agile-delivery-workflow` when the user explicitly asks for an MVP, early usable product, quick iteration, agile delivery, scout work, or a similar first-slice delivery.
- Use `$review-orchestration-playbook` as the only review entrypoint for named single, double, and triple review plus PR readiness.
- A named single review is exactly one clear/fresh-context Codex `reviewer` agent. Launch it with `fork_turns="none"` or the platform-equivalent zero inherited turns, run it read-only in its own clean Git worktree, and let it load every applicable skill, scoped `AGENTS.md`, and project-guidance file. Before launch, prove the frozen range and both endpoint trees are locally complete with lazy fetching disabled; do not let reviewer Git commands fetch missing objects or prompt for credentials. The orchestrator must identify the authoritative active playbook path/version; when this repository is reviewing its own policy migration, use the repo-local playbook from the frozen review head rather than an older installed copy. Give the reviewer only review-control metadata: the repository/worktree, frozen `base_sha..head_sha`, authoritative instruction source/version, instruction-loading order, read-only/evidence limits, focus/non-goals, and output contract. The reviewer must obtain and inspect the diff itself with bounded Git/tool calls; never prebuild or inject the full diff into its prompt.
- A named double review is that single-review agent plus an actual Anthropic Claude Code process launched directly in a different independent read-only workspace over the same frozen `base_sha..head_sha`; the supplied-diff/private-minimal-Git `isolated_review` helper is not this lane. A separately requested GitHub Copilot diagnostic never satisfies or increments the named double-review shape.
- For the Claude lane's accepted real-`HOME` native sandbox, treat outside-workspace read exclusion as prompt/model scope. Native `allowRead` is not a global host-read whitelist: launch must request global `denyWrite` and critical-sensitive-root `denyRead`; those requested controls define the native-sandbox enforcement boundary, while sandboxed Bash may technically read another host path not covered by `denyRead`. Record them as requested configuration because Claude Code 2.1.212 init/capability output does not attest the final merged sandbox or managed permission arrays.
- A named triple review is the named double review plus a trustworthy terminal current-head GitHub Codex result on a supported GitHub Cloud PR requested with exact `@codex review`. A bare named-review request is report-only: it does not authorize branch creation, push, PR creation, or PR branch/metadata changes; bare triple authorizes only the scoped review-request comment on an already-existing supported PR. If GitHub Codex is unavailable because there is no PR, the integration/host/identity is unsupported, the host is `sqbu-github.cisco.com`, or the operating identity is in `{hoteng, hoteng_cisco}`, report `effective double`; never claim triple. An authenticated provider rejection may prove that no run started and the integration/service is unavailable; missing response or generic failure is inconclusive. After acknowledgement/run/review activity proves start, malformed/stale/ambiguous/incomplete evidence is `triple-inconclusive`, not double fallback.
- The low-level `isolated_review` helper is diagnostic-only and records `named_lane_eligible=false`; it never counts toward single, double, or triple review. It uses a supplied diff plus helper-private minimal Git, defaults to a clean exact-head snapshot, and permits a digest-bound WIP snapshot only after explicit `--include-source-wip` consent. WIP evidence never satisfies PR readiness. PR readiness adds CI, conversation, and branch/base gates, but no retired extra Codex gates.
- For low-level Claude diagnostics, preserve real `HOME` as the ordinary Claude CLI control plane, select authentication in `ANTHROPIC_API_KEY` > `CLAUDE_CODE_OAUTH_TOKEN` > local-login order, and treat the native sandbox as selected-deny plus prompt/model scope rather than a global host-read whitelist. Helper egress markers are only `explicit-claude-review` and `explicit-claude-with-copilot-fallback`. These helper contracts do not apply to the named direct Claude lane.
- Any unambiguous request classified as single, double, or triple review—including `single review`, `single code review`, `单重 review`, `单一 review`, `double`, `double review`, `double code review`, `双重 review`, `triple`, `triple review`, or `三重 review`—is contemporaneous user consent for scoped code-review egress to exactly that named shape. Single authorizes OpenAI Codex; double additionally authorizes Anthropic Claude Code; triple additionally authorizes GitHub Codex on a supported GitHub Cloud PR. It covers necessary tracked code from the named repository's frozen review head, bounded tool-derived review evidence, and the review prompt/result. The Codex `reviewer` agent receives the clean worktree and refs rather than an injected full diff; actual Claude Code reviews the same range from its independent read-only workspace. It does not authorize GitHub Copilot or another substitute reviewer. It excludes credentials, untracked files, unrelated repositories, and broad workspace or home-directory content. For an approval-gated Claude invocation, repeat this consent together with the exact repository and `base_sha..head_sha` in the escalation justification; do not rely on a generic external-review justification.
