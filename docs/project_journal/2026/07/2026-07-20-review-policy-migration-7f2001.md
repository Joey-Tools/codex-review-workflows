# Review Policy Migration

## Summary

- The review policy migration removes the former extra Codex PR-review and frozen-diff gates from PR readiness.
- Single, double, and triple review now share one progressive lane model instead of combining unrelated mandatory gates.
- The canonical Claude lane now records the accepted real-`HOME` selected-deny trust boundary without overstating native host-read isolation.

## Current State

- Single review is one dedicated fresh-context Codex reviewer launched with zero inherited turns in a clean Git workspace, with no prepared diff supplied to the reviewer.
- Double review adds an actual Claude Code review in a separate read-only workspace.
- Triple review adds exact `@codex review` on an exact-host `github.com` PR plus a complete terminal provider-authored GitHub Codex findings payload bound to the current PR head, whole-PR range, and isolated request; the request comment does not complete the lane by itself. For one unchanged head, allow at most one acceptable exact request and never post a second one. Re-read complete authenticated request history immediately before accepting any result. Server timestamps prove ordering, not request/run lineage: review/comment evidence is `triple-inconclusive` whenever an older request might overlap. Completion consumes the exact-bot review body plus every fully paginated associated inline review comment, or a terminal exact-bot issue-comment body; missing or ambiguous payload, terminal nature, or association is `triple-inconclusive`. An exact-App current-head post-request check/run proves service start only and never completion or clean/no-findings, even when `completed` / `success`; a same-App check may be unrelated and success may coexist with review findings.
- Directly known no-PR/unsupported-host/unsupported-identity evidence or an authenticated provider no-start rejection can make a requested triple an effective double. Missing response or generic failure is inconclusive; untrustworthy evidence after service start is triple-inconclusive instead of fallback.
- Former mandatory extra local PR-review gates are retired and no longer define the policy; their historical helper implementations do not satisfy a named lane.
- Named single review uses a dedicated fresh-context Codex reviewer in a clean Git worktree. Named double adds a directly launched actual Claude Code process in a second clean worktree. Neither lane receives a prepared diff.
- The low-level supplied-diff helper is explicitly ineligible for named-lane counting. Its stateful surface records `review_contract: supplied-diff-no-git` and `named_lane_eligible: false`; raw foreground or `stateful final` output is never a named-lane envelope.
- Claude launch requests global `denyWrite` and critical-sensitive-root `denyRead`; those requested controls define the native-sandbox enforcement boundary. Outside-workspace read exclusion remains a prompt/model rule because selected `allowRead` is not a global host-read whitelist and sandboxed Bash can technically read an un-denied host path.
- Claude Code 2.1.212 init/capability output is not evidence of the final merged sandbox, managed permission arrays, runtime path evaluation, or effective enforcement of the requested controls.
- A bare named-review request is report-only. Bare triple may request GitHub Codex only on an already-existing supported PR; branch creation, push, PR creation, and PR branch/metadata changes require separate authorization.
- Named local lanes deliberately use executable clean-worktree and behavioral read-only contracts. They do not require an unimplemented raw-object materializer, endpoint-only object store, immutable instruction snapshot system, or unique Git wrapper.
- Once the compatibility workflow lands on the default branch, a maintainer must invoke its input-free `workflow_dispatch` one time to backfill the legacy success status for pull requests that were already open. Each pass fully paginates authenticated `state=all` pull-request membership in creation order, so open/close transitions cannot move later records between pages, then validates and buffers all API-reported open heads without publishing. Only two consecutive matching canonical `(pull request number, current head SHA)` snapshots authorize publication of exactly that stable snapshot; duplicate cross-page evidence is retried, and a non-default-branch run or missing or malformed evidence fails closed. Failure to stabilize within six passes publishes nothing and fails. A stable empty open-PR snapshot publishes nothing and succeeds, callers cannot provide a SHA, and later opened, reopened, or synchronized heads remain covered by the ordinary event path.
- The compatibility workflow and its one-time backfill must be deleted as soon as repository and organization rulesets no longer require `codex/review-gate`.

Explicit-range-only standalone single/double has no selected PR and requires no PR probe; authenticated no-PR also has no comparison. Triple performs only directly provable pre-request unavailability checks, treats unknown integration state as an eligible candidate, and classifies service availability from authenticated rejection or start evidence after the exact request.
- The direct Claude lane now requires one leading `system/init`, one trailing terminal `result`, and fail-closed matching of the version-specific cwd, permission mode, exact tool/customization surface, requested model, verified CLI version, and selected authentication source. These reported fields are not promoted into proof of the final merged sandbox, managed permissions, or path evaluation.
- The real-`HOME` trust boundary now names ordinary CLI-owned authentication/runtime writes accurately: credential refresh and possible cache or tool-result artifacts are accepted publisher-verified CLI control-plane side effects, not model-authorized mutations. `--no-session-persistence` does not make real `HOME` immutable, and the lane does not claim a complete HOME-diff attestation.
- The former `codex-review-gate.yml` automation that auto-started an extra Codex PR gate on ordinary PR events was removed. Its filename and `codex/review-gate` context remain temporarily as a no-op compatibility status because repository ruleset `16583548` and inherited organization ruleset `16590367` still require that context. The shim posts no review request, starts no reviewer, and supplies no review evidence or named lane; PR readiness observes it only as a legacy required status. Its trusted default-branch manual backfill paginates the stable `state=all` membership in creation order, filters and validates open records after enumeration, and publishes only after two consecutive canonical open-head snapshots agree, so open/close transitions cannot silently skip a later page or leave success statuses from an unstable pass. The run is bounded to six passes; if it does not stabilize, it publishes nothing and fails closed. A stable empty open set publishes nothing and succeeds. Delete the shim and backfill after both rulesets are migrated. GitHub Codex itself is requested only by the named-triple exact-comment flow.
- Final fresh-context reviews also forced four sequencing/evidence fixes: PR range/head alignment now precedes every mutable readiness-state read; an existing unsupported PR cannot masquerade as the no-PR path; the parent names the exact installed or frozen repo-local authoritative playbook source; and structurally valid Claude permission/configuration and authentication failures use one deterministic classifier instead of conflicting with malformed-envelope handling.
- The main playbook now performs intended-range/current-PR-head alignment before any local lane whenever a PR is selected, matching `pr-readiness.md`. Explicit-range-only standalone single/double needs no PR discovery or head field; a triple whose PR cannot be discovered is `blocked-input` / `triple-inconclusive`, not an invented effective-double fallback.
- Claude Code 2.1.212 now fixes `apiKeySource` to exact string values (`ANTHROPIC_API_KEY` or `none`) and specifies terminal `result`, `modelUsage`, error, API-status, and permission-denial types and emptiness rules.
- The terminal fresh-context pass first bound GitHub Codex evidence by trusted server ordering to the exact current request: server `submitted_at`, `created_at`, or check `started_at` must be later than the request comment's API `created_at`; same-head artifacts from earlier requests are stale. A final semantic rereview closed the remaining attribution gap across every active entrypoint: timestamps do not prove request/run lineage, at most one acceptable exact request may exist for an unchanged head, no second request may be posted, complete authenticated request history must be re-read before acceptance, and possibly overlapping older-request review/comment evidence is triple-inconclusive. The final check-only correction made exact-App current-head post-request checks service-start evidence only: even `completed` / `success` cannot complete triple or prove no findings because a same-App check can be unrelated and can coexist with provider review findings. Triple completion now consumes a complete terminal exact-bot review body plus fully paginated associated inline comments, or a terminal exact-bot issue-comment body; missing or ambiguous payload, terminal nature, or association fails `triple-inconclusive`. Critical selected-PR metadata probes now preserve the discovered host with explicit `gh api --hostname <host>` REST calls. The migration also parameterized PR-head discovery so legal branch-name metacharacters cannot alter the REST query.
- Final whole-range review also closed partial selected-PR scope: authenticated base/head metadata and one locally computed merge base must match the full explicit range before local results count as whole-PR readiness or triple evidence. A same-head/different-base range remains caller-owned partial evidence and blocks PR-specific completion instead of being silently rewritten.
- The named Claude lane now has an executable pre-input exact-version gate. It ignores caller `PATH`, verifies the fixed signed `2.1.212` artifact before any version probe, and deterministically blocks the locally active `2.1.216` without executing it. The workflow never installs or switches Claude automatically; acquiring a missing exact version is a separately authorized official-installer workflow. Until then, requested double remains double-but-blocked, and an independently effective-double triple remains incomplete because the Claude lane did not complete.
