# Review Policy Migration

## Summary

- The review policy migration retires the former `independent-codex-pr-review` and `offline-frozen-diff-review` gates; neither remains part of PR readiness or named-lane counting.
- Single, double, and triple review now share one progressive lane model instead of combining unrelated mandatory gates.
- The canonical Claude lane now records the accepted real-`HOME` selected-deny trust boundary without overstating native host-read isolation.

## Current State

- Single review is one dedicated fresh-context Codex reviewer launched with zero inherited turns in a clean Git workspace, with no prepared diff supplied to the reviewer.
- Double review adds an actual directly launched Claude Code review in a separate lane-unique clean detached Git worktree at the same frozen head. The model and its tools remain read-only, but real `HOME` is the trusted Claude CLI control plane rather than an immutable review workspace.
- Triple review adds exact `@codex review` on an exact-host `github.com` PR plus complete current-head, whole-PR provider evidence. The current consumer contract is superseded and defined by `skills/review-orchestration-playbook/references/github-codex-evidence-authority.md`: request history controls whether the parent may post again, while the complete exact-bot provider snapshot determines the outcome without request/run attribution. Early or duplicate requests are reported as outcome-neutral warnings; the parent still posts at most one same-scope request and never a second or third. Exact-App check/run success remains service-start evidence only.
- Every selected PR now requires authenticated lifecycle `state=open`, `merged=false`, and `merged_at=null` before PR-specific lanes. Missing or contradictory lifecycle is `pr-lifecycle-unverified`; closed-unmerged is `selected-pr-closed`, and merged is terminal. An observed non-open state at a mandated snapshot after request/service start remains triple-inconclusive; the point-in-time probes do not claim to prove that no intermediate close-and-reopen occurred. GitHub review completion accepts only exact states `COMMENTED`, `APPROVED`, or `CHANGES_REQUESTED`; `PENDING` waits, while `DISMISSED`, missing, and unknown states fail closed.
- A post-request base-only retarget invalidates the old whole-PR range without authorizing a second request on the unchanged head. The honest terminal state is readiness `blocked-input` (`base-changed-same-head`) and effective `triple-inconclusive` until a separately authorized ordinary change creates a new head; the workflow never manufactures an empty or anchor commit to escape that blocker.
- Only directly known no-PR/unsupported-host/unsupported-identity evidence can currently make a requested triple an effective double. The fixed authority baseline has no accepted no-start body grammar and an empty accepted structured capability/installation schema set, so integration/service uncertainty and free-form exact-bot prose cannot prove that fallback. Missing response remains pending while bounded waiting is meaningful and becomes inconclusive after exhaustion; untrustworthy evidence after service start is triple-inconclusive instead of fallback.
- `independent-codex-pr-review` and `offline-frozen-diff-review` are retired contracts, not dormant compatibility gates. Their historical implementations do not satisfy a named lane and cannot block PR or merge readiness.
- Named single review uses a dedicated fresh-context Codex reviewer in a clean Git worktree. Named double adds a directly launched actual Claude Code process in a second lane-unique clean detached Git worktree and preserves real `HOME`. Neither lane receives a prepared diff. The publisher-verified CLI may perform ordinary CLI-owned authentication refresh and write cache, tool-result, or other runtime artifacts in real `HOME`; those trusted control-plane side effects are not model-authorized review mutations.
- The low-level supplied-diff helper is explicitly ineligible for named-lane counting. It uses a helper-owned detached workspace backed by private minimal Git, records `review_contract: supplied-diff-private-git` and `named_lane_eligible: false`, and never turns raw foreground or `stateful final` output into a named-lane envelope.
- The low-level helper's broker, staged carrier, exact local-login credential-lock catalog, full refresh transaction, guarded writeback, and recovery contracts remain current helper-only policy. The named direct real-`HOME` lane does not inherit or claim them. Both paths share floating executable eligibility, publisher provenance, capability checks, and preflight-bound strict stream validation, but their later authentication and runtime-isolation contracts are deliberately separate.
- Required PR/master exact-secret admission is now the direct `isolated_review secret-admission` Git-tree scan under `review_contract: admission-only-no-reviewer`. It never creates a review workspace, diff, prompt, reviewer state, authentication, egress, or provider process and has only terminal exits `0` clean, `1` violations, and `75` inconclusive. Clean admission also requires complete temporary cleanup; a proved violation remains exit `1` if later location mapping or cleanup fails, while a clean scan with incomplete cleanup becomes exit `75`. The stateful helper pair remains optional compatibility evidence only when that low-level reviewer was independently requested.
- Claude launch requests global `denyWrite` and critical-sensitive-root `denyRead`; those requested controls define the native-sandbox enforcement boundary. Outside-workspace read exclusion remains a prompt/model rule because selected `allowRead` is not a global host-read whitelist and sandboxed Bash can technically read an un-denied host path.
- Current named-direct and low-level-helper policy accepts publisher-verified strict stable Claude Code `>=2.1.211,<3.0.0`; `2.1.212` is only a per-version schema baseline, not a pin. Each selected release is bound to its exact signed per-version manifest, platform artifact size, and SHA-256. Before any credential or review input, the preflight runs credential-free `--version` and `--help` capability probes against the same private digest-verified temporary executable snapshot, reverifies that snapshot, and binds the accepted capability and stream-profile digests. The later strict stream validator must consume that exact accepted preflight binding. The named direct review then launches the revalidated installed executable path, not the erased preflight snapshot and not the helper launcher. These gates still do not attest the final merged sandbox, managed permission arrays, runtime path evaluation, or effective enforcement of the requested controls. Helper local-login guarded writeback may additionally require a catalogued signed artifact, but that helper-only transaction constraint does not pin named-direct or explicit helper API-key/OAuth review to one Claude patch release.
- A bare named-review request is report-only. Bare triple may request GitHub Codex only on an already-existing supported PR; branch creation, push, PR creation, and PR branch/metadata changes require separate authorization.
- Named local lanes deliberately use executable clean-worktree and behavioral model/tool read-only contracts. The trusted real-`HOME` Claude CLI control-plane exception above is intentional. The lanes do not require an unimplemented raw-object materializer, endpoint-only object store, immutable instruction snapshot system, or unique Git wrapper.
- Once the compatibility workflow lands on the default branch, a maintainer must invoke its input-free `workflow_dispatch` one time to backfill the legacy success status for pull requests that were already open. Each pass fully paginates authenticated `state=all` pull-request membership in creation order, so open/close transitions cannot move later records between pages, then validates and buffers all API-reported open heads without publishing. Only two consecutive matching canonical `(pull request number, current head SHA)` snapshots authorize publication of exactly that stable snapshot; duplicate cross-page evidence is retried, and a non-default-branch run or missing or malformed evidence fails closed. Failure to stabilize within six passes publishes nothing and fails. A stable empty open-PR snapshot publishes nothing and succeeds, callers cannot provide a SHA, and later opened, reopened, or synchronized heads remain covered by the ordinary event path.
- The compatibility workflow and its one-time backfill must be deleted as soon as repository and organization rulesets no longer require `codex/review-gate`.
