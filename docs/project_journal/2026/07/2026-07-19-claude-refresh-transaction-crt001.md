# Claude Refresh Transaction Lock

## Summary

- Serialize each catalogued Claude local-login attempt before the first host credential read and through runtime refresh, quiescence, final drain, and verified host persistence on macOS, Linux, and WSL2.
- Retain shared lock directories as a fail-closed stale fence when rotation persistence or writer quiescence remains uncertain.
- Keep API-key mode independent of local-login carrier coordination.

## Current State

- The process supervisor exposes a post-cleanup quiescence callback only after the child is reaped and its supervised process group is absent.
- macOS carrier selection, broker execution, snapshot validation, and host persistence reuse one outer refresh-lock lease.
- Linux/WSL2 credential staging, watcher writeback, final drain, and cleanup reuse one borrowed-descriptor host lease while private staged-carrier locks remain separate.
- Linux/WSL2 release and retain-only cleanup re-read the lease terminal state after every interruptible release or abandonment result, preserve the first control-flow winner, and use the same deletion-prohibited non-destructive abandonment path when repeated entry interruptions require recovery.
- Abandoned leases publish an irreversible deletion-prohibition latch before interruptible diagnostic work, stop their heartbeat, close owned descriptors when quiescence permits, retain every shared lock directory that was created or may have been created, and cache a descriptor-bound recovery diagnostic that never points at lexical paths. A later public release can only resume non-destructive abandonment settlement and descriptor cleanup; it can never reopen directory deletion.
- Abandonment cleanup tracks `NOT_STARTED`, `RESUMABLE`, and `SETTLED` independently from its cached diagnostic. It consumes each descriptor at most once, settles close failures or reuse ambiguity as retained residue, and exposes one atomic snapshot that distinguishes lifecycle terminality from verified descriptor closure. A private publication slot remains bound to a distinct, never-promoted descriptor fallback through every retained state, including `SETTLED`, and becomes empty only after release is published. Linux/WSL2 reads that slot directly instead of retaining a mutable diagnostic alias or inferring completion from `fstat`; an already-frozen control-flow winner remains descriptor-only even after settlement.
- Abandonment and destructive release acquire the operation `RLock` through a lease-published five-state handoff that covers both the callee and caller result boundaries. Unresolved ownership survives the interrupted call and is reconciled before every later terminal-state return, including normal context exit after physical lock cleanup; only the original thread object may release it, another thread fails closed without replacing it, and terminal handoffs are cleared by identity. The public `released` flag reports only physical lock-directory and descriptor cleanup, while the atomic retention snapshot remains nonterminal until any published handoff is cleared. Abandonment records raw error chronology before classification, recovers the earliest control-flow from a bounded 16-node active context chain, immediately binds descriptor-only recovery evidence, and uses a method-level second selector so one later cleanup signal cannot replace that winner.
- The irreversible deletion-prohibition latch is published before `RESUMABLE` becomes visible. A release caller that already passed its pre-lock checks therefore cannot enter destructive cleanup after an asynchronous interruption between abandonment state stores.
- Refresh-lock heartbeat threads inherit the forwarded-signal mask so the main thread retains control-flow priority while it attaches recovery evidence.
- Linux/WSL2 refresh-lease acquisition, watcher startup, and deferred cleanup use caller-owned forwarded-signal mask handoffs. The previous mask is published before the helper return boundary, an interruption after the blocking syscall either rolls back inside acquisition or transfers restoration ownership to the caller, and cleanup still releases or abandons an already-acquired host lease before propagating the first control-flow error.
- Linux/WSL2 starts a dedicated cleanup coordinator while forwarded signals are blocked and before acquiring the host refresh lease. The coordinator inherits that mask, owns the explicit-context lease from acquisition through one linearized `NORMAL_RELEASE`, `RETAIN`, or `CANCEL` decision, and publishes terminal state only after the heartbeat, watcher/source-descriptor handoff, and descriptor-bound lock recovery have settled. Missing signal-mask ownership, watcher-start uncertainty, carrier-cleanup failure, or repeated control-flow interruption therefore retains the private carrier and shared locks instead of entering destructive cleanup. Pre-thread startup failure has a distinct terminal cancel path, while decision-wait interruptions are recoverable inside the masked worker.
- If cleanup signal masking fails after the Linux coordinator thread failed before entry or before acquiring a lease, unmasked cleanup now selects the coordinator's terminal `CANCEL` path instead of retrying an impossible `RETAIN` decision forever. Coordinators that own a lease still retain it to a proven terminal state.
- Linux/WSL2 bounds the outer unmasked fail-closed cleanup callback to eight attempts. Persistent callback failure keeps the staged credential carrier and descriptor-bound shared-lock evidence attached to an ordinary diagnostic, so cleanup pauses without hanging or deleting uncertain state.
- Coordinator retention bounds heartbeat-quiescence recovery to two abandon/release cycles. A heartbeat that remains live is settled as terminal descriptor-bound residue without closing descriptors or unlinking shared lock directories, so callers receive a deterministic fail-closed result instead of waiting forever.
- Watcher stop and coordinator source-anchor retention bound every start-state, stop-admission, stop-event, deadline, quiescence, and descriptor-handoff transition to two attempts. Exhausting one phase still advances the remaining fail-closed phases; an unproven handoff leaves the source descriptor coordinator-owned, the carrier retained, and a deterministic diagnostic instead of spinning the cleanup worker.
- The Linux/WSL2 staged-credential watcher publishes a local `UNKNOWN` start state before the interruptible native `Thread.start()` boundary and promotes it to `CONFIRMED` only after startup returns or `_started` is observed. Stop admission closes before one sticky deadline is published; UNKNOWN confirmation and join share that remaining budget. A timeout, confirmation error, join error, or unreadable start handoff leaves quiescence unproven, hands the source anchor to the late watcher, retains the private carrier, and abandons the host lease with descriptor-bound evidence. A transient false `is_alive()` result before `_started` publication can never authorize cleanup.
- The common process supervisor publishes a caller-owned `UNKNOWN` start state immediately before entering `Popen` and promotes it to `CONFIRMED` only after Python stores the returned process handle. A constructor failure or control-flow interruption at the call-result boundary therefore leaves both Linux/WSL2 and macOS carrier cleanup with `may_have_started=True` and no false quiescence proof, so the private carrier and shared refresh locks remain retained.
- macOS refresh observation and verified host commit use matching monotonic write generations; a later incomplete `W` invalidates an earlier commit proof and retains the stale fence.
- A verified host commit is not the terminal proof: the final carrier snapshot records its own matching generation only after revalidation succeeds, so a changed snapshot, ordinary inspection error, or forwarded signal retains the stale fence even after writeback completed.
- macOS terminal settlement treats signal-mask acquisition failure as unsafe, prepublishes a caller-owned handoff before blocking forwarded signals, and commits mask ownership only after the previous mask is stored. Interruptions before that commit roll back once inside acquisition; interruptions after it leave pending-signal consumption and the single final restore to the outer handoff. The handoff blocks signals only across state inspection and unsafe-lock abandonment, binds pending-signal recovery and first-primary selection before restoring the caller mask, and never consumes a pending signal already owned by an outer mask; a safe terminal state still releases normally.
- The outer macOS local-login lease is retain-only through its public API and exposes no releasable callback or mutable authorization. Its coordination body exits normally only after terminal settlement proves process quiescence, persistence, and the final carrier generation; that normal exit synchronously removes the locks before the terminal signal mask is restored, while every exceptional exit retains them. A safe reviewer error is deferred until after the normal-exit release and then propagated during signal handoff completion.
- Every direct refresh-lock acquisition publishes an empty cold lease to a mandatory caller-owned handoff object before acquiring either shared lock, registers a pending acquisition before each `mkdir`, and adopts each inspected lock before it crosses an internal return boundary. The caller confirms transfer only after local assignment, so interruptions at raw `mkdir`/`open` results, internal resource assignments, the callee return, or the caller `STORE_FAST` boundary retain a descriptor-bound recovery fence or safely release a fully owned unexposed lease on macOS, Linux, and WSL2. Ambiguous non-`FileExistsError` `mkdir` failures remain pending and fail closed instead of assuming that no directory was created.
- If control flow interrupts abandonment-diagnostic publication, a preconstructed descriptor-bound fallback remains available while bounded shutdown and descriptor settlement continue; the winning error therefore reports descriptor-bound recovery without silently leaving a stale fence or attributing a retargeted lexical path to the retained directory.
- A final carrier proof records both proof presence and its exact write generation. Generation zero is valid only after an explicit snapshot proof, and a started reviewer cannot release the outer lease after a failed or interrupted zero-update revalidation.
- Every auxiliary-thread and carrier-coordination signal-mask crossing prepublishes a caller-owned mask owner, queries the caller mask before applying forwarded-signal blocking, and restores exactly once after the complete acquisition/start/quiescence lifecycle. Thread startup atomically publishes one immutable caller-owned `NOT_STARTED`, `UNKNOWN`, or `CONFIRMED` outcome snapshot with its selected error; all eight production callers execute cancel, close, quiescence, unlink, scrub, or retention through safety `finally` paths before merging handoff and cleanup errors. Post-start control flow therefore cannot be hidden by a cached clean result or a caller `CALL`-to-assignment interruption, and control-flow winners remain acyclic on Python 3.10 and newer; validation control flow retains a generic persistence-failure diagnostic without copying unverified recovery paths.
- Common process execution and Claude carrier coordination retain caller-owned signal-mask ownership until restoration succeeds. Both acquisition result boundaries are covered, transient restore failures receive one bounded retry without clearing ownership early, and Linux/macOS quiescence merges restoration failures behind the first control-flow winner instead of replacing it.
- Python opcode safety probes normalize the owned and borrowed fast-local load forms introduced by Python 3.14 only where both forms preserve the asserted handoff semantics. Owned load-to-store boundaries remain strict and do not accept borrowed loads.
- Concurrency interruption regressions do not infer context-manager boundaries from CPython `with` opcodes. Instrumented release locks, heartbeat events, and prearmed retention-snapshot boundaries now exercise the same ownership and lifecycle transitions across supported Python runtimes.
- Broker and proxy serve threads start with cancellation prearmed, clear it only on successful admission, and release their serve gates through independent nested `finally` paths. An interruption at either the cancellation call entry or result therefore still wakes, quiesces, closes, unlinks, and safely scrubs or retains the associated credential state.
- A macOS broker teardown `BaseException` is converted into an unquiescent shutdown result at the credential-server boundary. The existing fail-closed path then abandons the runtime, detaches pending publication when possible, performs bounded recovery, marks handler quiescence unproven, and only then propagates the original control-flow error so the shared refresh locks cannot be released on an incomplete teardown.

- A declared macOS cleanup residue keeps the outer refresh transaction abandoned when no-follow identity validation succeeds, is inconclusive, or is interrupted; control-flow errors are propagated only after the stale fence and recovery diagnostic are attached.
- If refresh-lock abandonment is itself interrupted while another control-flow error is already primary, the original primary identity wins while descriptor-bound lock recovery metadata is copied onto it before cleanup notes or an acyclic Python 3.10 fallback graph are attached; a detached secondary node preserves the cleanup signal and every independent cause/context branch without copying the edge back to the primary.

- macOS starts the refresh-lock heartbeat under the forwarded-signal mask and revalidates the lease after carrier selection but before broker exposure.

- Linux/WSL2 keeps the borrowed host refresh lease through payload scrubbing and verified staged-carrier cleanup; cleanup failure or interruption abandons the lease before propagating the primary error.
