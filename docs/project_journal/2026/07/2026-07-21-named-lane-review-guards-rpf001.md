# Named Lane Review Guards

## Summary

- Close the final named-lane safety and evidence-correlation gaps without restoring retired prepared-diff or hidden review gates.

## Current State

- Each local lane now begins with a trusted `materialize-worktree` guard that initializes a private repository, imports only the hard-bounded frozen base/head reachable-object closure, audits that exact inventory before checkout, and materializes only the exact head with hooks, filters, fsmonitor, ambient configuration, and submodule recursion disabled. The existing `validate-worktree` guard is then the first worktree-status query immediately before reviewer launch; clone/fetch/upload-pack, `git worktree add`, or any earlier status query is a safety failure.
- Source selection now binds the exact `.git` marker by device, inode, file type, and owner. A linked-worktree gitfile must keep both its forward `gitdir:` target and the admin directory's back-pointer paired to that marker. Marker `mtime`, `ctime`, and `nlink` churn is deliberately non-semantic and remains accepted when those identity and target bindings stay exact. Control files are opened no-follow and nonblocking, then checked as stable owned regular files; every storage revalidation rereads both linked directions, so FIFO replacement and later back-pointer drift fail closed.
- The materializer binds the exact source marker/admin/common/object directories, requires Git 2.45.0 or newer, reads source configuration only as a bounded no-include byte stream, rejects shallow/alternate/promisor dependencies, and exposes the source object store only through a temporary destination-scoped alternate. It caps object count, logical bytes, checkout entry/blob/path bytes, and compressed pack bytes, imports the exact manifest through strict `index-pack`, verifies the destination inventory equals that closure, disables commit-graph and multi-pack-index consumption for every guard call and later bare Claude Git, rejects fsck policy overrides and bitmap state, and runs bounded full object-validity `fsck` before checkout. Its cleanup-to-receipt transaction defers forwarded signals until either a complete flushed success receipt or a complete flushed failure payload names every retained control/worktree path.
- Source pack `.bitmap` files are rejected before object traversal, `pack-objects` explicitly uses `--no-use-bitmap-index`, and the private target remains bitmap-free. Materializer `ls-tree` and validator `ls-tree`/`ls-files`/`status` now share a raw-output ceiling derived from the 100,000-entry, 64-MiB aggregate-path envelope and the exact SHA-1 or SHA-256 object-ID width.
- The standalone post-materialization validator still treats smudge-only configuration as inert during its status/read-only phase, but the formal materializer rejects executable smudge configuration before checkout. That narrower distinction preserves validator compatibility without allowing a named lane to execute candidate-selected transforms during construction.
- Both local lanes run a parent-owned tracked-symlink containment check before reviewer launch. Stable in-worktree source links remain allowed, while escaping or unstable links and symlinked guidance are rejected.
- GitHub Codex completion and no-start evidence must bind to the exact request/run or satisfy the sole-unresolved/no-intervening fallback. A full SHA corroborates artifact scope but never identifies which request caused the response, including when an older-head request may execute after a push and review the new current head. Timestamp proximity alone cannot complete or downgrade triple review.
- The direct Claude lane uses a process-only bounded supervisor with a finite deadline, bounded streams, and process-group cleanup. Linux cleanup also reaps a direct child after its process group contains only zombies. Partial, over-limit, timed-out, or incompletely cleaned output is inconclusive.
- `run-claude` now requires the accepted parent-private `--preflight-result`, matches the requested source path and relevant identity/policy fields, and copies from an opened no-follow source descriptor into a private digest-verified mode-`0500` launch snapshot. Launch binding deliberately ignores source `mtime`, `ctime`, and `nlink` churn, while signed size/SHA-256 or relevant identity/policy drift fails closed. The snapshot—not the mutable raw host path—is executed, so raw-path replacement after binding cannot alter the launched bytes; no parent before/after raw-path check is required. The process receipt records the preflight digest, source binding, signed artifact binding, and `launch_binding.mode: verified-snapshot`. Snapshot creation/handoff and later cleanup are separate forwarded-signal-masked critical sections; between them the bounded supervisor owns structured signal forwarding and process cleanup. Cleanup uses the retained parent descriptor plus the guard-created leaf identity, while lexical parent identity/owner/mode checks remain output-publication policy. Incomplete cleanup returns structured `snapshot-cleanup` evidence with the original `process_reason` plus exact `retained_path` when the lexical binding is revalidated, or descriptor-bound `retained_locator` device/inode/leaf evidence after lexical drift.
- Before stream validation, the parent compares the receipt's exact preflight SHA-256, resolved source path/identity, and signed artifact size/SHA-256 against the accepted binding. The validator separately rereads the preflight result and does not consume `launch_binding`.
- The same absolute monotonic deadline now begins before the CLI reads the control prompt through EOF and can only tighten the duration bound. Snapshot copy and full rehash also consume that same budget. The subsequent worktree Git resolution receives at most the smaller of its normal 30-second cap and the remaining shared budget before process supervision receives what remains. A writer that sends a short prompt but withholds EOF or a slow Git probe that exhausts the remainder becomes an inconclusive deadline result without launching the reviewer, while termination signals during prompt wait become structured `inconclusive` / `forwarded-signal` evidence.
- Worktree validation accepts safe system symlinks in path ancestors while still rejecting a symlink leaf, so canonical paths such as macOS `/tmp` do not become false safety failures.
- Claude process supervision is explicitly limited to the initial supervisor process group and inherited streams. It does not overclaim containment of descendants that deliberately escape with `setsid()` or `setpgid()` and close those streams.
- Claude output publication stays anchored to prevalidated parent-directory descriptors across process launch, rejects parent identity drift without treating content-derived directory metadata as identity, and rolls back through the retained descriptors.
- Tracked symlink targets are read in one aggregate 30-second Git batch with explicit entry, per-target, and total-output limits instead of one process deadline per symlink.
- Materialized gitlinks are rejected before the guard invokes `git status`, preventing a pre-existing gitfile from redirecting that query into external repository metadata.
- Repository-visible `include.path` and `includeIf.*.path` keys are blocked before status or reviewer execution, including inactive conditions and benign or malformed targets. Included values are not accepted as safety configuration; initial bounded repository-identity probes may still parse the target and fail closed, so the guard does not claim a no-read boundary. Other safety-relevant configuration is evaluated only from direct local/per-worktree values with includes disabled. Raw gitlinks without `.gitmodules` or name/path mappings still participate in repeated global `submodule.active` pathspec matching, alongside direct path mapping, per-name active-boolean precedence, and URL registration evidence. Status is forced to honor executable-bit drift even when `core.fileMode=false`. Every direct Git alias and direct executable clean/process filter plus `diff.external`, driver command, and textconv settings are rejected, while unrelated invalid booleans, explicit per-name false, smudge-only filters, required-only settings, and non-command diff metadata do not become false findings. Any parent- or reviewer-owned diff rendering must disable both external diff and textconv.
- Direct `core.fsmonitor` is validated before any status or reviewer Git command. Unset and Git-false values are allowed; built-in daemon, no-value, and path hook values are rejected without execution. Direct local/per-worktree precedence remains supported, so a worktree `false` can safely override a local path.
- Self-policy migration now keeps candidate-head Markdown available as review subject and scoped guidance while pinning the reviewer profile, prompt, guard, launcher, complete in-repo runtime closure, and external Python interpreter to independently trusted control-plane evidence. The runtime package exposes the legacy helper entrypoint lazily. The guard's default profile compiles only its three manifest-bound package/runtime sources; both the Claude preflight and stream validator profiles use exact nine-source closures, and the post-acceptance `classify-review-result` profile uses only `review_runtime` plus `review_runtime.review_result`. The classifier source is part of the canonical manifest, is compiled from the initially bound bytes, and is completely reread immediately before its already loaded `main` runs, so result disposition cannot bypass the bundle digest or ordinary-import boundary. Every profile records exact `.py` origins and keeps the package closed to ordinary import resolution, so same-name top-level modules, native extensions, and prebuilt bytecode cannot enter the closure. The release key, compatibility profile, audited schema baseline, versioned profile schema, capability source, and applicable `fd_exec.py` process companion are retained as initially validated immutable bytes and completely reread immediately before consumer entry. Formal descriptor-backed launches inject the initially bound `fd_exec.py` bytes into `common.py`, validate and compile those exact bytes, and execute them through an isolated `-I -B -S -c` bootstrap without reopening the companion path. Cross-read comparison protects exact content rather than inode or timestamp continuity: a same-content ordinary-file replacement remains valid, while any byte drift is rejected. The deterministic control manifest also binds the PR-readiness, GitHub-probe, base-only retarget, egress-consent, and review-result decision policy used to interpret review outcomes. The guard is non-executable source with no shebang and requires a revalidated absolute native Python `>=3.10` launched through `-I -B -S` under a fixed clean environment, so ambient `PATH`, `PYTHONPATH`, global/user site initialization, `.pth` files, `sitecustomize`, loader, virtualenv, and shell controls cannot select or preconfigure it. Every formal command resolves that guard from the manifest root through `skills/review-orchestration-playbook/scripts/named_lane_guard`; no flattened `<bundle>/scripts` path is accepted. The formal Claude preflight also ignores ambient `HOME`: it derives and validates the current POSIX account home, then binds that canonical path directly into the selector so ordinary user-level installs remain discoverable under the clean launcher. The bundle's absolute source and publisher release/frozen-commit version accompany a deterministic control-file manifest digest verified before each launch/spawn and after each lane. Candidate-head scripts cannot bootstrap their own formal review; an incompatible new guard activates only after the prior trusted policy reviews, merges, and releases it.
- The Codex reviewer receives one exact sanitized Git argv prefix and cannot use bare Git, alternate wrappers, extra environment state, changed safe flags, or another worktree. Every diff-producing invocation explicitly disables external diff and textconv.
- The canonical direct Claude lane is local-login-only in trusted real `HOME`. It has no API-key or OAuth-token interface, reports forbidden refresh or non-local-only credentials as `blocked-authentication`, rejects npm/NVM shebang shims under canonical provenance, and does not expand trusted `PATH` to accommodate them.
- Test-oriented `run-claude` CLI overrides can equal or tighten, but never raise, the 1,800-second timeout, 64 MiB per-stream, and 256 KiB prompt production caps. Direct Python API callers are bound by the same ceilings.
- Ambient `NODE_EXTRA_CA_CERTS` remains excluded by default. A value-free explicit opt-in validates the configured absolute non-symlink regular file without exposing its path in the guard argv; the direct lane deliberately does not claim the helper's copied/attested CA guarantees.
- Claude output publication uses a lane-unique current-user-owned mode-`0700` directory, temporary signal handlers, and an explicit commit point. Publishing the complete output pair and emitting plus flushing its complete `launch_binding` receipt now share one signal-safe transaction: a pre-receipt signal or receipt write/flush failure rolls back the pair, while a signal after the flushed receipt cannot turn committed output into an untrustworthy retry obstacle. Final and temporary cleanup preserve identity drift already observed before unlink. The contract explicitly excludes the non-portable stat-to-unlink race from non-cooperative same-UID writers instead of claiming an impossible conditional unlink.
- The guard does not prepare a diff, inspect ordinary file contents, broker authentication, replace the actual reviewer, or add another PR-readiness gate.
- The reusable filesystem-hardening rule is property-scoped: first name whether a check protects object identity, content, or a safety policy, then compare only metadata relevant to that property. Tests cover benign provider/filesystem metadata churn separately from true replacement, content drift, and policy drift; unreadable remains distinct from missing or mismatched. In particular, a renamed output directory does not prevent descriptor-bound cleanup of the exact guard-created snapshot, but it still blocks publication through the changed lexical path.
