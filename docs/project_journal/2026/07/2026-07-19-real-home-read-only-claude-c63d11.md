# Use Real-HOME Read-Only Claude Reviews

## Summary

- Claude reviews now use one combined runtime: the verified Claude Code control plane receives the current account's real `HOME`, while model tools remain read-only inside a helper-owned detached Git worktree.
- Clean exact-head content is the default. Explicit `--include-source-wip` captures staged, unstaged, and non-ignored untracked files into a scanned, digest-bound review-only artifact.
- Authentication follows `ANTHROPIC_API_KEY` > `CLAUDE_CODE_OAUTH_TOKEN` > ordinary local login. The helper opaque-forwards only the winning explicit value without parsing, logging, staging, brokering, or persisting it; Claude Code continues to own ordinary local-login discovery and refresh state.

## Current State

- Each review workspace is a literal detached Git worktree backed by a helper-owned minimal Git database. It does not register in the source common Git directory, touch source refs, or conflict with other worktrees.
- Default preparation rejects dirty source state. WIP capture requires explicit consent, uses the same immutable workspace and runtime boundary, and binds the complete captured content to a recorded digest.
- WIP evidence is suitable for fixed-artifact feedback but not for formal PR-readiness or merge-ready exact-commit gates; those gates require a clean committed head.
- The detached workspace, private Git database, logs, and state now live outside the source checkout under the fixed canonical system temporary root `/tmp`. The root must be a root-owned exact-`01777` real directory; current-user-owned exact-`0700` effective-UID and canonical-source-path-digest namespaces contain each private run.
- Source `.codex-tmp` content receives no helper status filter: ordinary Git ignore/status rules apply, any reported entry makes clean mode dirty, and WIP capture treats the path as reserved. Retained `/tmp` state is not durable across reboot or host temporary-file cleanup.
- New external review state uses schema/marker v2. Exact historical v1 state under `<canonical-source>/.codex-tmp/isolated-review-*` remains manageable in place by status/wait/final/cleanup, including the bounded cleanup worker, but cannot launch a reviewer or satisfy the v2 retained-fallback gate.
- On WSL2, `/proc/self/mountinfo` must prove both the source checkout and external review container use supported local native Linux filesystems; Windows-backed provenance is blocked and unproven provenance is inconclusive.
- Only Claude Code `2.1.212` is eligible after publisher-provenance, public-capability, and structured-output checks; other releases fail closed until the behavioral contract is revalidated and deliberately advanced. Every accepted review stream proves effective `dontAsk` mode, the exact `Read`/`Grep`/`Glob`/`Bash` tool set, the requested model, and compatible authentication evidence. `Read(./**)` records intended detached-workspace access and unmatched requests are denied; deny-first rules protect real-HOME secrets plus `/proc` and `/dev`. Sandboxed Bash requests global `denyWrite`, critical-sensitive-root `denyRead`, authentication-variable removal, and explicit `allowRead` entries for the detached worktree and private Git view. Those entries are not a global host-read whitelist: paths not covered by `denyRead` remain technically readable, so the prompt/model contract forbids all outside-workspace reads. Claude Code 2.1.212 does not expose the final merged sandbox, managed permission arrays, or path-rule evaluation; the report records requested configuration rather than claiming independent enforcement proof, and admin-managed policy remains part of the trusted ordinary CLI control plane.
- The verified control plane may use ordinary Claude Code local login and refresh behavior from real `HOME`. Explicit API-key or OAuth-token values are forwarded only according to precedence and are requested to be removed from sandboxed Bash commands. Valid `auth status --json` evidence is parsed before return-code classification, so Claude Code's nonzero `loggedIn: false` result becomes `blocked-authentication` with the carrier-specific recovery action. The model-backed launch disables Claude Code's broad subprocess scrub because v2.1.212 otherwise forces effective permission mode to `default`; credential-free probes retain it. Hooks, MCP, plugins, skills, and slash commands are separately disabled and checked. The prompt requires read-only behavior, and an exact post-attempt validation rejects any observable worktree, private-Git, diff, or prompt mutation before accepting a result. This does not claim proof against transient writes or out-of-workspace side effects, including ordinary real-HOME control-plane caches or tool-result artifacts.
- The real-HOME resolver clears inherited `XDG_CONFIG_HOME`, preventing alternate Claude configuration discovery outside the authorized home. Output redaction covers explicit authentication values plus credential-bearing proxy URLs and the bounded raw, stripped, strict-percent-decoded, existing-escape-preserving, WHATWG-canonical, special-URL-authority, percent-case, and Claude all-`Cc`-stripped userinfo/password forms that may reach logs. Malformed encoding, decoded NUL, ambiguous literal `@`, and standalone credential variants shorter than eight bytes fail closed before launch. Empty effective userinfo, routing-only proxy endpoints, and `NO_PROXY` values are excluded from unsafe global replacement; all proxy variables remain denied to sandboxed Bash.
- Strict Claude JSONL output is consumed as a single-pass stream that retains only the required init/result events and aggregate error state, avoiding Python-object amplification from a bounded file containing many small records.
- Sensitive-content and escaping-symlink checks cover the exact selected artifact, including non-ignored untracked files in WIP mode, before any provider egress.
- WIP validation also scans the original source `HEAD`-to-snapshot delta paths and original-`HEAD`-side raw blobs from the helper-private Git database. The complete snapshot scan covers the current side, so deleting or reverting a sensitive committed file in the WIP snapshot cannot leave it review-readable through `git show` without blocking egress.
- WIP capture distinguishes deleted tracked endpoints from paths whose content must be read. This prevents a case-insensitive filesystem from resolving the deleted side of a case-only rename to the new path and materializing both spellings.
- Clean/WIP source classification now uses helper-owned exact-`0700` scratch under the verified canonical `/tmp` root instead of caller `TMPDIR`; bounded preparation spill files use the same fixed root. Its source-inspection Git database is anchored at the actual source `HEAD`, with only the source object directory and exact per-worktree index attached. Bounded source `info/exclude` bytes are frozen into that database. A config-only query uses ordinary system/global/common/worktree precedence to select the effective `core.excludesFile`, resolves relative values against the actual source root, freezes at most 1 MiB into a separate helper-private file, and projects only typed `core.ignoreCase` and `core.precomposeUnicode` path semantics. Bounded `status`/`diff`/`ls-files`/`ls-tree` still suppress operational source-local, system, and global Git configuration and retain deliberate mode-change hardening. Files ignored by the user are neither classified as WIP nor copied, scanned, or sent to a reviewer, while source-local hooks, clean/process filters, aliases, and diff drivers cannot execute.
- Gitlinks in either the actual source `HEAD` tree or active index now fail closed before source `status` or `diff`, including staged deletion or replacement, so the helper never recurses into source submodules or consumes their local Git configuration. Gitlinks present only in the selected review artifact remain supported as uninitialized, unfetched directories.
- WIP regular-file contents and symlink-target bytes now consume the same 512 MiB aggregate capture budget. Blob creation uses one bounded `fast-import` session with exact SHA-1/SHA-256 digest verification, and all raw-path removals/additions use one NUL-delimited `update-index --index-info` session. This preserves non-UTF-8, newline, tab, directory/file-transition, duplicate-blob, deletion-only, and source-race semantics while removing the previous per-path subprocess amplification.
- Linux/WSL2 preflight now requires and identity-verifies both native `bubblewrap` and `socat`. The selected tool directories are bound ahead of other host-tool directories in the final Claude `PATH`, and exact name resolution is rechecked before launch so the native sandbox cannot consume an earlier shadow executable.
- Endpoint commit and tag metadata scanning now includes both the complete joined raw Base64 body and strict decoded bytes of structured `gpgsig`, `gpgsig-sha256`, and nested `mergetag` signature blocks, closing both wrapped-raw and encoded-credential paths into the reviewer-readable private Git database.
- Legacy synthetic exemptions remain tree-content-only. Endpoint commit messages, ordinary headers, decoded signature metadata, and nested `mergetag` metadata accept public authoring-pool values but reject every exact catalog legacy value even when its tree exemption is selected.
- Range admission now runs against a short-lived helper-owned sanitized Git view before the formal review container is allocated; legacy synthetic-provenance ancestry checks reuse the same primitive. Only the source object directory is attached and commit-graph acceleration is disabled. Source Git configuration, replacement refs, `.git/info/grafts`, and cached commit-graph parent edges therefore cannot forge the committed graph accepted as frozen review evidence. When an ancestry query returns false, a bounded zero-output `rev-list --quiet --missing=error` walk must first prove both endpoint histories traversable before `merge-base` status `1` can mean a legitimate unrelated history; missing objects remain no-fetch, fail-closed errors even on Git 2.43's ambiguous status behavior.
- Private review Git commands and the exact canonical SHA-1/SHA-256 repository configuration now explicitly disable reflog creation rather than relying on bare-repository defaults. The external preflight still rejects any unexpected common or per-worktree `logs` inventory, and cleanup remains available for that fail-closed state. Stale commit-graph regressions also accept both supported Git behaviors at the untrusted default-query boundary: some versions trust the cached graph, while older versions reject the missing object before the helper's explicit no-graph query runs.
- Detached-worktree creation now materializes and securely hardens the exact empty per-worktree `refs` directory instead of relying on Git-version-specific side effects. Git 2.43-compatible regressions remove the directory after `worktree add` and prove that preparation recreates the canonical `0700` layout; injected refs remain rejected. The two stale commit-graph fixtures also accept Git's documented false-ancestry return code `1` before independently proving that the helper's explicit no-graph query fails closed.
- Private Git byte admission now budgets endpoint blobs, tree metadata, and commit metadata before adding separate pack-encoding, WIP-storage, and pack-sidecar margins. The larger aggregate limits no longer reject near-limit endpoint metadata that the public snapshot contract already permits, while a separate smaller loose-object cap avoids widening the per-file mutation surface. Boundary tests combine synthetic object-size metadata with a real small WIP pack, sidecar, and loose-object fixture to prove exact-limit acceptance plus one-byte-over rejection without allocating giant fixtures. WIP mode projection remains aligned with Git's owner-execute-bit semantics; group-only and other-only execute bits are deliberately normalized to `100644` and covered through the real source-WIP path.
- Stateful v2 cleanup now treats the detached worktree and private Git database as independent cleanup targets. A retry runs when either target remains and clears a previous cleanup error only after both are gone, closing the crash window between worktree removal and private-database removal without changing legacy v1 semantics. A separate regression proves that genuine staged-only content is already included in the final materialized WIP snapshot.
- Explicit state cleanup now validates state/layout and probes the runner lock directly instead of routing through output-producing `status`. Cleanup therefore remains available when the caller's current proxy/auth carriers cannot form a safe redaction set, while an actually held runner lock still retains both workspace and private Git state with exit code `3`.
- Synthetic legacy-count manifests now use schema v3. Source-WIP preparation and validation independently bind raw and unembedded counts for the base tree, final snapshot, and committed source `HEAD`, so a WIP deletion cannot hide a `1 -> 2 -> 1` increase that remains readable through private Git. Reviews without a selected legacy exemption avoid the additional full source-`HEAD` count scan.
- The helper-backed whole-range Codex review found that logging only the original credential-bearing proxy URL did not cover Claude/Bun-normalized URLs or bare userinfo/password. The fix now binds each accepted credential component to the complete bounded output-variant set above, rejects ambiguous or globally unsafe cases before execution, and adds regressions for HTTP/HTTPS special authority recovery, mixed literal-plus-existing escapes, Unicode, all control-character diagnostics, empty userinfo, malformed inputs, and stateful redaction reuse. The focused rereview returned `No findings.`
- The latest helper-backed whole-range Codex review found that source `status`/`diff` could still execute repository-local clean/process filters and that explicit cleanup unnecessarily depended on the caller's current output-redaction carriers. Source classification now uses the helper-owned Git context and fixed-root scratch described above; actual source `HEAD` and active-index gitlinks, caller `TMPDIR`, stale commit graphs, linked-worktree indexes, and source-local filters have dedicated regressions. Cleanup now shares a redaction-independent runner-terminal observer with `status`, preserving missing/invalid exit handling and child reaping. Focused read-only re-audits of both repairs returned no implementation findings.
- A later helper-backed current-head Codex review found that suppressing all source config also discarded effective repo/worktree ignore semantics, so a case-variant or locally ignored untracked file could cross the WIP consent boundary. Effective excludes now follow system/global/common/worktree precedence and are frozen into helper-private state; `core.ignoreCase` and `core.precomposeUnicode` are the only source path-semantics settings projected into operational inspection. Repo-local relative excludes, linked `config.worktree` precedence, case-insensitive ignore matching, immutable excludes snapshots, and safe-config allowlisting have dedicated regressions.
- GitHub Codex also found that raw substring replacement could corrupt an absolute workspace or diff path embedded in a URI or longer token. Claude prompt projection now rewrites only standalone path tokens and workspace descendants; ambiguous URI-embedded or suffix-extended occurrences fail closed.
- GitHub Codex review found the Git 2.43 worktree-refs and stale-graph-test portability gaps above, plus a mismatch between absolute projected prompt paths and the relative `Read(./**)` rule. Claude prompts now keep both workspace and primary diff relative to the fixed review cwd. A separate Bash finding was rejected with retained Claude Code 2.1.212 evidence: `--tools` controls visibility, while the built-in non-prompting read-only classifier allowed `wc`/`pwd`/`cat` and denied a non-baseline compound command and `touch`; no broad Bash allow rule was added. The focused rereview of these fixes returned `No findings.`
- Cleanup-lock creation avoids a redundant `fchmod(0600)` when the newly created file already has the exact private mode. This closes a concurrent first-open metadata race without weakening the subsequent path/descriptor identity, owner, link-count, mode, and metadata-stability checks; genuinely restrictive umasks still take the corrective path.
- Claude Code 2.1.212 creates an empty `.claude/.cc-writes` directory when its native Bash sandbox first runs. The provider records exact pre-launch absence plus any existing real `.claude` parent's filesystem identity, then uses no-follow directory descriptors to verify current-user ownership, `0700` mode, empty contents, and stable parent/child identity. The staging entry itself is atomically moved into helper-private quarantine, re-proved against the opened inode, rechecked as empty, and only then removed non-recursively. It performs the same conservative cleanup and exact workspace validation after the managed process group has completed bounded termination/I/O teardown on a supervision exception, while preserving the primary exception and recording cleanup rejection only as a secondary redacted diagnostic. A new empty parent is independently moved into helper-private quarantine and identity-checked before removal; a swapped candidate at either layer is retained there and rejected rather than restored through a replace-capable rename. Pre-existing WIP entries are not cleaned, disappeared or replaced parents are rejected, and the unchanged exact workspace validator still decides every remaining shape.
- A final canonical local Codex review found that a helper `--prompt-file` previously replaced the default outside-workspace, read-only, and findings-only discipline before the selected-deny Claude launch. The final Claude stdin now always sandwiches projected supplemental instructions between an authoritative opening boundary and a closing reminder, so custom focus cannot remove the model-level scope contract; the complete protected prompt is still subject to the existing byte limit. Adversarial override and direct-launch wiring regressions bind this behavior.
- After review policy migration #68, `isolated_review` is explicitly low-level diagnostic infrastructure with `review_contract: supplied-diff-private-git` and `named_lane_eligible: false`. Canonical named review uses a zero-inherited-turn Codex `reviewer` agent in one clean worktree, direct actual Claude Code in another, and current-head GitHub `@codex review` as the third lane when available. The helper's real-HOME/private-Git clean-or-explicit-WIP contract remains supported but never satisfies a named lane or PR-readiness gate.
