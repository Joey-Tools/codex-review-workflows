# Claude 2.1.226 Guard-Managed Session Environment

## Summary

- Preserve the named-direct lane's global native-sandbox `denyWrite: ["/"]`
  request while accommodating Claude Code 2.1.226's pre-Bash
  `$HOME/.claude/session-env/<uuid>` creation.
- Keep one fresh UUIDv4 session ID guard-owned while managing its filesystem
  namespace through descriptor bindings and a cooperative `$HOME/.claude`
  namespace lease; pass the same ID through `--session-id`, clean the selected
  leaf nonrecursively after supervision, and bind the reported stream back to
  the launch receipt without claiming `mkdir` origin or continuous custody.

## Current State

- The global compatibility policy remains `>=2.1.211,<3.0.0`. Only the
  named-direct feature gate at `>=2.1.226` requires the additional
  `--session-id` capability and guard-managed session lifecycle; older releases
  and both helper profiles keep their existing interfaces.
- Before creating or opening the shared `session-env` parent, the launcher
  acquires an exclusive advisory BSD `flock` on the stable no-follow descriptor
  for real `$HOME/.claude`. It retains that lease through snapshot creation,
  handoff, supervision, positive quiescence, and cleanup or complete
  recovery-evidence construction. The lease serializes only controls that take
  the same lock; the signed Claude CLI's idempotent `mkdir` and non-cooperative
  same-euid host processes remain host-TCB assumptions.
- The launcher rejects caller session/resume/cloud/background/worktree
  selectors and retries rather than deliberately adopting an `EEXIST` UUID
  leaf. Parent and leaf identities are the objects first observed through
  no-follow opens, not proof that the preceding `mkdir` created those objects
  or that the guard retained continuous namespace custody.
- After the verified launch snapshot is ready, handoff revalidates parent/leaf
  device, inode, directory type, current-account uid/access/ACL policy, exact
  leaf mode `0700`, and emptiness. `mtime`, `ctime`, `nlink`, and benign parent
  child-entry churn are irrelevant. Hostile same-euid parent/leaf
  `mkdir`-to-open substitution, handoff/runtime ABA, and final
  `stat`-to-`rmdir` replacement remain excluded from the guarantee.
- Cleanup protects leaf object identity, owner/access policy, and emptiness.
  It ignores `mtime`, `ctime`, `nlink`, and benign parent child-entry churn,
  uses only nonrecursive `rmdir`, and retains an authoritative path or
  descriptor-bound recovery locator when safe removal cannot be proved.
- The bounded supervisor's positive process-quiescence callback publishes only
  the proof needed to authorize post-launch removal. The outer guard performs
  the descriptor-relative cleanup later under its own successfully acquired
  forwarded-signal mask. If the proof callback does not run, the guard retains
  the possibly active leaf, emits `process-leak`, preserves the original
  supervision failure in `process_reason`, and reports its parent/leaf recovery
  identity instead of treating an outer `finally` block as quiescence proof.
- A successful receipt records the guard-owned session ID and the namespace,
  parent, and leaf first-bound identities. The parent passes that
  receipt-derived ID through
  `--expected-session-id`; guarded init output must contain the same canonical
  UUIDv4. Missing, malformed, or conflicting correlation evidence is
  inconclusive. Existing intermediate bindings remain mandatory by event
  family, while terminal `session_id` remains optional and must match when
  present.
- The parent also exact-checks the receipt's closed session-environment
  descriptor: `identity_binding` is
  `first-no-follow-open-after-exclusive-mkdir`; `creation_origin_proven` is
  boolean `false`; `creation_origin_guarantee` is
  `best-effort-122-bit-uuidv4-leaf-immediate-nofollow-open-cooperative-claude-control-directory-flock-same-uid-host-tcb`;
  `namespace_exclusivity_guarantee` is
  `exclusive-advisory-claude-control-directory-flock-cooperative-same-uid-host-tcb`;
  `cleanup_guarantee` is
  `descriptor-custody-emptiness-revalidation-nonrecursive-rmdir-cooperative-claude-control-directory-flock-same-uid-host-tcb`;
  and `cleanup_observation` is `selected-name-absent-after-rmdir`.
- No `allowWrite` exception is added. The preexisting selected leaf observed at
  handoff lets the CLI's idempotent `mkdir` complete without widening the
  sandboxed Bash child's write surface.
