# Claude 2.1.226 Guard-Owned Session Environment

## Summary

- Preserve the named-direct lane's global native-sandbox `denyWrite: ["/"]`
  request while accommodating Claude Code 2.1.226's pre-Bash
  `$HOME/.claude/session-env/<uuid>` creation.
- Let the trusted launcher own one fresh UUIDv4 session, precreate and bind the
  exact empty leaf, pass the same ID through `--session-id`, clean the leaf
  nonrecursively after supervision, and bind the reported stream back to the
  launch receipt.

## Current State

- The global compatibility policy remains `>=2.1.211,<3.0.0`. Only the
  named-direct feature gate at `>=2.1.226` requires the additional
  `--session-id` capability and guard-owned session lifecycle; older releases
  and both helper profiles keep their existing interfaces.
- The launcher rejects caller session/resume/cloud/background/worktree
  selectors, creates the shared `session-env` parent only when its existing
  real-`HOME` custody path is safe, and creates an exact mode-`0700`,
  current-user-owned empty leaf through retained directory descriptors.
- Cleanup protects leaf object identity, owner/access policy, and emptiness.
  It ignores `mtime`, `ctime`, `nlink`, and benign parent child-entry churn,
  uses only nonrecursive `rmdir`, and retains an authoritative path or
  descriptor-bound recovery locator when safe removal cannot be proved.
- A successful receipt records the guard-owned session ID and removed leaf
  identity. The parent passes that receipt-derived ID through
  `--expected-session-id`; guarded init output must contain the same canonical
  UUIDv4. Missing, malformed, or conflicting correlation evidence is
  inconclusive. Existing intermediate bindings remain mandatory by event
  family, while terminal `session_id` remains optional and must match when
  present.
- No `allowWrite` exception is added. The guard-created preexisting leaf lets
  the CLI's idempotent `mkdir` complete without widening the sandboxed Bash
  child's write surface.

## Next Steps

- Release and activate the updated trusted bundle before using this new guard
  as formal review control. A prior trusted bundle remains authoritative for
  reviewing this self-policy migration.
